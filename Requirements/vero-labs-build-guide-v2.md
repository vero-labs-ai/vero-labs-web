# Vero Labs Website Build Guide — v2 (ground-up rebuild)

This file replaces the previous build guide entirely. Discard the dark "engineering instrument"
direction: no slate backgrounds, no terminal chrome, no amber-on-dark, no JetBrains Mono, no
Space Grotesk. v2 is a light, editorial, print-inspired system. The copy still lives in
`vero-labs-website-content.md` — that file governs the words; THIS file overrides every visual
note in it (any mention there of dark surfaces, amber, or monospace styling is superseded).

Read this whole file before writing code. It encodes researched constraints, not preferences.

---

## 1. The brief

Vero Labs is a two-person applied AI studio in Bangalore selling to skeptical technical and
semi-technical buyers (CTOs, product heads, founders). The site's one job: make two engineers
with one anonymized production system look like the obviously credible choice. The buyer has
seen a hundred AI-agency sites this month; ninety of them look identical and AI-generated.
The strategy is therefore not decoration but distinction-through-evidence: the site should read
like the published field report of people who ship — real schematics, real numbers, real call
transcripts — set in an editorial system nobody's site-builder produces by default.

New since v1, and now first-class content: the demo video and call-clip assets exist. The site
must showcase them, not just describe capability.

Single page + a `/demo` page. Light. Editorial. Evidence-dense. Quiet confidence.

## 2. Research findings this guide is built on (June–July 2026)

### 2a. The AI-slop catalog — what instantly reads as generated
The tells are now literally codified (public detectors catalog ~46 patterns). The ones that
matter for us, all BANNED in this build:

- Purple/violet-to-blue gradients anywhere; gradient text; cyan-on-dark
- Inter or Roboto as the typeface; "system default" typography generally
- The template layout: centered hero + two buttons → three icon feature-cards → testimonial
  carousel → pricing → three-column footer
- Glassmorphism, blur cards, glow borders, colored box-shadow glows
- Dark-neon "terminal/cyberpunk by default" (v1 lived adjacent to this — that's why it's dead)
- Warm cream/beige page background "reached for by reflex" (the 2025–26 AI-startup look; also
  now a flagged tell — so the fix is white, not oat)
- Thick one-side accent borders on cards; hairline border + wide diffuse shadow on one element
- Over-rounding (cards at 24px+ radius turning everything into soft blobs)
- Hand-coded SVG mascots/illustrated scenes; emoji as icons; icon grids
- Fake dashboards, fake logos, invented testimonials or metrics

### 2b. What escapes it — the documented counter-moves
- Distinctive typography is repeatedly identified as the single fastest escape from generic;
  the credible pattern is a characterful display face paired with a clean text face (the
  Stripe pattern: bespoke-feeling serif headlines + neutral sans body).
- Editorial layout over SaaS-marketing layout: long-form columns, pull quotes, inline figures,
  numbered sections — "think magazine, not marketing page."
- Monochrome + one signal color used with conviction (validated by current award-winning B2B
  work: black-and-white platform, single orange marking CTAs and key moments).
- Real artifacts instead of stock: actual product output, actual data, actual documents.
- Explicit negative constraints written into the design system — telling the builder what NOT
  to produce is as load-bearing as the tokens.

### 2c. Reference pool (study these lanes, don't clone any one site)
- SiteInspire's editorial/typographic lane: European sensibility — generous whitespace,
  restrained color, strong type, content hierarchy over decoration. This is v2's home lane.
- Long-form journalism typography (NYT-style feature layouts): oversized display headlines,
  clear reading measure, figures embedded in the text flow.
- Print engineering documentation: spec sheets, schematics, redlined drawings — thin ink
  lines, labeled figures, tabular data. Content-native for an engineering studio.
- Minimalist portfolio playbook: whitespace, functional type, visible grid; work first.

### 2d. The honest caveat
Light editorial is also being adopted fast; no palette is permanently slop-proof. The durable
differentiation in this design is the material: our schematics, our latency table, our
transcript excerpts. Those cannot be generated by a site builder because they are the actual
work. Protect that principle in every future edit: when in doubt, add evidence, not decoration.

## 3. The concept: "The Field Report"

The site is designed as the published technical report of a working studio — part journal
article, part engineering spec sheet. A reader should feel they've opened a document written
by the two people who built the thing, not a marketing page assembled around it.

Concretely, the system has four signatures:

1. **Editorial masthead & numbered sections.** The page is structured like a journal issue:
   a masthead, a contents line, sections numbered 01–07, hairline ink rules dividing them.
2. **Redline schematics.** The two technical diagrams (call loop, architecture) are drawn as
   print-style engineering figures: thin ink lines on white, small mono labels, with the
   accent color used the way engineers use a red pen — to mark the live path, the bottleneck,
   the thing you must notice. Each figure gets a caption ("Fig. 1 — One conversational turn").
3. **Margin annotations.** Key sections carry short side-notes in the outer margin (small
   mono type): the honest asides ("the LLM is the bottleneck; we say so"), definitions,
   cross-references. This is the editorial device that makes the page feel authored.
4. **Evidence blocks.** Transcript excerpts, the latency spec table, the payload excerpt, and
   the demo player are typeset as figures within the flow — exhibits in the report.

## 4. Design tokens

### Color — "ink on paper, one red pen"
```
--paper:        #FFFFFF   /* page background. White. Not cream, not oat, not #FAFAF5 */
--paper-tint:   #F6F6F3   /* only for evidence blocks (tables, transcripts) — a whisper of tone */
--ink:          #171715   /* primary text; near-black warm ink, never pure #000 */
--ink-soft:     #55554F   /* secondary text, captions, margin notes (AA on white: ~7:1) */
--rule:         #D9D9D4   /* hairline rules and table borders */
--redline:      #C8371E   /* THE accent: links, marks, live-path in figures, key numbers */
--redline-ink:  #A32C16   /* darker accent for small text where extra contrast helps */
```
Rules of use: the page is 95% ink-on-white. `--redline` appears the way red ink appears on a
reviewed drawing — sparingly and meaningfully: the primary CTA, inline links, the marked path
in each figure, one number per evidence block. If a screen has more than a handful of red
elements visible at once, it's wrong. No gradients anywhere. No colored backgrounds except
`--paper-tint` on evidence blocks.

### Typography (all Google Fonts; load with display=swap)
```
Display:  "Newsreader"       — headlines, section titles, pull quotes (use its italic!)
Text:     "Instrument Sans"  — body, UI, buttons, nav
Data:     "IBM Plex Mono"    — figures, labels, tables, margin notes, the masthead meta line
```
Never Inter, Roboto, Space Grotesk, or JetBrains Mono. Newsreader carries the editorial
authority; Instrument Sans stays invisible; Plex Mono marks "this is data/evidence."

Scale (desktop; clamp down ~15–20% on mobile):
```
Hero headline:      clamp(2.8rem, 6.5vw, 5rem), Newsreader 500, line-height 1.05, tracking -0.015em
Section title:      clamp(1.8rem, 3.5vw, 2.6rem), Newsreader 500
Pull quote:         1.5rem, Newsreader italic 400, --ink
Body:               1.0625rem, Instrument Sans 400, line-height 1.65, max-width 68ch
Figure caption:     0.85rem, IBM Plex Mono 400, --ink-soft
Margin note:        0.8rem, IBM Plex Mono 400, --ink-soft
Section number:     0.85rem, IBM Plex Mono 500, --redline  (e.g., "03")
Masthead meta:      0.8rem, IBM Plex Mono, letter-spacing 0.06em, uppercase
```

### Space, shape, rules
```
Content grid:       12-col, max 1120px; text column 68ch; outer margin column for annotations
Section padding:    7rem desktop / 3.5rem mobile between numbered sections
Radius:             0 on rules/tables/figures; 6px MAX on buttons and the video player. Nothing rounder.
Rules:              1px solid --rule, full text-column width, above each section title
Shadows:            none. Flat print. (The video player may have a 1px --rule border instead.)
```
Horizontal hairline rules are structural (print-native), and permitted ONLY as full-width
section dividers and table borders — never as decorative accent bars, never colored, never
partial-width underlines beneath titles.

### Motion
Minimal and print-respectful. Permitted: a single fade-up (12px, ~350ms) per section on first
scroll into view; the redline path in each schematic may draw in once (~600ms) on reveal;
link underlines may thicken on hover. Nothing else — no parallax, no floating elements, no
cursor effects. Full `prefers-reduced-motion` support: everything static and visible.

## 5. Signature elements — build specs

### 5a. The masthead (top of page)
Not a SaaS navbar. A journal masthead:
```
VERO LABS                                          Applied AI Studio — Bangalore
─────────────────────────────────────────────────────────────────────────────────
No. 01 · Field Report · 2026            Contents: Demo — Work — Method — Contact
```
Wordmark in Newsreader 600; the meta line and contents in Plex Mono. The contents links are
the nav (anchor links). On scroll, a slim sticky bar appears with just the wordmark + contents
links + one redline "Start a project" text-link (not a filled button in the bar).

### 5b. Redline schematics (Fig. 1 and Fig. 2)
Inline SVG, hand-authored, no diagram libraries.
- Fig. 1 — "One conversational turn": Customer → Telephony (Plivo) → STT (Deepgram Nova-3)
  → LLM (Azure GPT-4.1) → TTS (ElevenLabs) → Customer. Thin --ink strokes (1.25px), nodes as
  simple rectangles with 0 radius, labels in Plex Mono. The live audio path drawn in
  --redline; the LLM node annotated "≈1.0–1.7s — dominant latency" with a small redline
  circle-mark, exactly like a reviewer's pen.
- Fig. 2 — "System architecture": Salesforce ↔ middleware ↔ FastAPI pipeline ↔ Bolna stack,
  with the post-call GPT-5.4 extraction branch. Same language. Redline marks the real-time
  JSON push path.
- Every figure sits in the text column with a mono caption beneath: "Fig. 1 — One
  conversational turn. Typical perceived latency 1.5–2.5s."
- Mobile: figures rearrange vertically; captions persist.

### 5c. Evidence blocks
A shared component: `--paper-tint` background, 1px --rule border, 0 radius, generous padding,
mono typesetting inside. Four instances:
1. **Transcript excerpt** (from the real test calls, PII-masked): 4–6 lines, speaker labels
   ("AGENT", "CALLER") in small caps mono, Devanagari inline as-is. One exchange only — the
   barge-in correction is the strongest.
2. **Latency spec table**: the honest table (first audio 44–77ms; STT 17–50ms; LLM first
   token 1.0–1.7s marked in redline; TTS 350–1000ms; perceived turn ~1.5–2.5s).
3. **Payload excerpt**: ~10 lines of redacted JSON, keys in --ink, one key value in redline.
4. **The demo player** (see 5d).

### 5d. The demo, first-class
Section 01 right after the hero. Embed the recorded walkthrough (YouTube unlisted or Loom
embed) inside an evidence block titled "Exhibit A — recorded walkthrough (2:40)". Beneath it,
two audio elements with one-line mono captions ("caller interrupts mid-spell — agent recovers")
using the cleaned clips. When the live callable number exists, it gets a single redline line
here: "Or call the demo agent yourself: +91 ……". Nothing on this page autoplays.

### 5e. Margin annotations
On ≥1100px viewports, an outer margin column carries 3–6 short mono notes aligned to their
passages (CSS grid; `position: sticky` not required). Under 1100px they collapse into small
indented notes beneath the paragraph. Content examples: "No RAG in the live path — per-call
structured context, for determinism." / "We publish engineering numbers, not outcome claims."

## 6. Page structure & layout

Single page, numbered sections. ASCII wireframes are intent, not pixel spec.

### Hero (no section number; sits under masthead)
```
  We build AI systems that survive          (Newsreader, oversized, left-aligned, 2 lines max)
  contact with production.

  Vero Labs is a two-person applied AI studio in Bangalore. We design,
  build, and run the systems — multi-agent, voice, computer vision,
  applied ML — end to end, and stay on to operate them.        (body, 68ch)

  [ Start a project ]      Watch the demo ↓                    (one redline button + text link)

  multi-agent · voice · computer vision · applied ml           (mono, --ink-soft)
```
Left-aligned. No centered stack, no gradient, no illustration, no product screenshot collage.
The headline may differ from the content file's original if that file's hero reads dark-brand;
prefer the wording above or the content file's alternates — editorial voice, plain claim.

### 01 — Demo ("Exhibit A")
Evidence block with the video, two audio clips, optional call-the-agent line (5d).

### 02 — What we do
Four capabilities from the content file — but NOT as an icon card grid. Typeset as an
editorial list: each capability is a Newsreader run-in heading followed by its 2–3 sentence
body, separated by hairline rules, in a two-column layout on desktop (2×2 of text, no cards,
no icons, no boxes). Margin note: "Stated as things we build. One has a live case study below."

### 03 — Selected work (the case study — the longest section, a magazine spread)

### 04 — Method (How we work)
The four steps from the content file as a numbered editorial sequence (mono numerals 01–04 in
redline, run-in bold titles, prose) — a list in text, not four boxes.

### 05 — The studio (Team)
Two short bios side by side, names in Newsreader, roles + links in mono. No photos required;
if any, real photographs only — never generated, never stock.

### 06 — Contact
```
  06  CONTACT
  ── rule ──
  Have a workflow that needs AI in production?          (section title)
  [ 2 sentences from content file ]
  [ Email Vishal ]   [ Email Alakh ]                    (one redline primary, one ink outline)
  vishal@vero.co.in · alakh@vero.co.in · Bangalore      (mono)
```

### 07 — Colophon (footer)
A print colophon, not a link farm: one line naming the studio and city; the contents links
repeated inline; GitHub handles; "© 2026 Vero Labs." Optionally one honest colophon sentence:
"Set in Newsreader, Instrument Sans, and IBM Plex Mono. Hand-built; no site builder." That
line is on-thesis — include it.

### /demo page
Same masthead + tokens. The video, all cleared audio clips with captions, Fig. 1, the latency
table, one CTA. This is the URL used in outreach and Upwork bids.

## 7. Explicit negative constraints (enforce verbatim)

Never, anywhere on this site:
- Dark theme, dark sections, or dark hero bands. The page is white end to end.
- Cream/beige/oat page background. `--paper-tint` is for evidence blocks only.
- Gradients of any kind; gradient text; glow effects; glassmorphism; blur overlays.
- Inter, Roboto, Space Grotesk, JetBrains Mono, or system-default typography.
- Icon grids, emoji icons, feature cards with icons, three-card hero-adjacent layouts.
- Testimonial carousels, logo walls, star ratings, invented metrics, fake dashboards.
- Illustrated mascots, hand-coded decorative SVG scenes, stock or AI-generated imagery.
- Cards with one-side accent borders; hairline border + big soft shadow combos; radius >6px.
- Centered long-form text; centered hero stacks.
- Colored section backgrounds for rhythm ("alternating gray band" pattern).
- Parallax, cursor followers, floating shapes, tilt effects, scroll-jacking.
- Em dashes and emoji in rendered copy (per the content file's rules).
- Any client or sample-tenant name; any business-outcome metric.

## 8. Components & quality bar

- Buttons: primary = --redline fill, white text, 6px radius, Instrument Sans 500; secondary =
  1px --ink outline. Hover: darken to --redline-ink / fill tint. Visible focus ring (--redline,
  2px offset) on every interactive element.
- Links: --redline-ink text with underline (real underlines; this is an editorial site).
- Tables: hairline --rule borders, mono numerals, no zebra striping, no rounded corners.
- Accessibility floor: one h1; landmarks (header/nav/main/section/footer); logical heading
  order; body contrast ≥ 7:1 (ink on white passes), small mono notes ≥ 4.5:1; figures carry
  <figure>/<figcaption> and meaningful aria-labels describing the flow; keyboard-navigable;
  `prefers-reduced-motion` honored; audio/video never autoplay and have visible controls.
- Performance: hand-written HTML/CSS/JS, no framework, no build step. One CSS file, one small
  JS file (scroll reveals + nothing else). Three font families via one Google Fonts link,
  `display=swap`, weights kept minimal (Newsreader 400/500 + italic; Instrument Sans 400/500;
  Plex Mono 400/500). Target: sub-150KB excluding fonts and the video embed.
- Responsive: test 360 / 768 / 1280. Margin notes collapse under 1100px; figures go vertical;
  the 2×2 capability layout stacks.

## 9. Tech & deployment (GitHub Pages)

Static, no build step, relative paths only (`./styles.css`, `./main.js`, `./assets/…`) so the
site works at a user site root, a project-site subpath, and later a custom domain unchanged.

```
/
├── index.html
├── demo/index.html
├── styles.css
├── main.js
├── .nojekyll
├── README.md
└── assets/  (favicon.svg — a plain ink "V·L" monogram; schematic SVGs if externalized;
              audio clips; poster image for the video)
```

Deploy (project site, recommended): repo `vero-labs` under Dark8203 →
```bash
git init && git add . && git commit -m "Vero Labs site v2"
git branch -M main
git remote add origin https://github.com/Dark8203/vero-labs.git
git push -u main origin  # (git push -u origin main)
```
Then Settings → Pages → Deploy from branch → `main` / root. Custom domain later: add a `CNAME`
file containing `vero.co.in`, point DNS per GitHub's current custom-domain docs, enforce HTTPS.

Local preview: `python3 -m http.server 8000`. Check the three breakpoints and reduced motion.

## 10. Definition of done

- [ ] Reads as an authored editorial document: masthead, numbered sections, rules, margin
      notes, figure captions all present.
- [ ] White page end to end; redline used sparingly and meaningfully; zero gradients/shadows.
- [ ] Newsreader / Instrument Sans / IBM Plex Mono loaded and used as specified; no Inter.
- [ ] Both schematics hand-drawn as inline SVG in the print style, with captions and redline
      marks; draw-in animation degrades under reduced motion.
- [ ] Demo section embeds the real video + two cleaned clips; nothing autoplays; /demo page live.
- [ ] All four evidence blocks present with real (sanitized) material; no invented data.
- [ ] Every item in §7 verified absent. Run the checklist literally before shipping.
- [ ] Copy matches the content file (visual notes there superseded); no client names; no
      outcome metrics; no em dashes.
- [ ] Accessibility floor met; 360/768/1280 clean; deploys on Pages with relative paths.

## 11. Edit discipline (for every future change)
When adding anything, ask: is this evidence or decoration? Evidence (a figure, a number, a
transcript, a real artifact) strengthens the thesis. Decoration converges the site back toward
the statistical average. Add evidence.
